# Task 07 — Корпоративный dev-контур: nginx-прокси + SSH-туннель + мок вебхука

|                 |                                                       |
| --------------- | ----------------------------------------------------- |
| **Приоритет**   | 1 — мок делается сразу, туннель — после выделения VM  |
| **Зависимости** | нет (проверка подписей вебхуков доедет из Task 09)    |
| **Блокер**      | nginx + туннель ждут VM (шаг 0); мок от VM не зависит |

## Контекст

Сейчас `npm run sshtunnel` пробрасывает порт 3005 на личный VPS для GitHub webhooks. Для корпоративного контура нужна та же схема на корпоративной VM, плюс возможность разрабатывать вообще без внешнего VCS — моком вебхука. VM ещё не выделена — поэтому задача разбита на независимые части: мок стартует немедленно, инфраструктура доезжает позже.

## Объём работ

### 0. Запросить VM (блокер для частей 1–2)

- VM в сегменте, доступном с GitLab-сервера; открытые 80/443 от GitLab
- SSH-техаккаунт для туннеля: без shell, только port forwarding (`Match User` + `AllowTcpForwarding` в sshd_config)
- Права на установку nginx (или готовый nginx с правом на конфиг)

### 1. Мок вебхука (НЕ зависит от VM — делать первым)

- `scripts/mock-webhook.mjs` + `fixtures/webhook/` — POST готового payload на localhost:3005, без реального VCS и туннеля
- `fixtures/webhook/github-pr-opened.json` — сейчас; gitlab / bitbucket добавят задачи 10/11
- `npm run mock:webhook [-- --vcs github --event opened]`
- в dev-режиме подпись не проверяется, в production — обязательна (см. Task 09)

### 2. nginx на корпоративной VM (после шага 0)

- reverse proxy: `location /webhook/ { proxy_pass http://127.0.0.1:3005; }` (туннельный порт на самой VM)
- TLS за корпоративным CA (если SEG требует), иначе plain HTTP внутри контура
- ограничение по source IP VCS-серверов, если возможно
- проксировать `/health` — для проверки живости туннеля

### 3. SSH-туннель dev → VM (после шага 0)

- `ssh -N -R 3005:localhost:3005 <vm>` (reverse; `GatewayPorts` не нужен — nginx ходит на 127.0.0.1 самой VM)
- keepalive на dev-машине (Windows): `npm run sshtunnel:corp` по образцу текущего `sshtunnel` (ServerAliveInterval/CountMax) + автоперезапуск
- устойчивость к обрывам: скрипт-цикл или sshd-опции на стороне аккаунта

### 4. Документация

- runbook в README: запрос VM → конфиг nginx → туннель → регистрация webhook URL в GitLab → мок как fallback для локальной разработки

## Критерии приёмки (DoD)

- [ ] VM запрошена; когда выделена — webhook из корпоративного GitLab доходит до dev-машины через nginx+туннель
- [ ] Туннель переживает обрыв связи (переподъём скриптом)
- [ ] `/health` через nginx отвечает при живом туннеле
