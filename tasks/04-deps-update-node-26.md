## Контекст

Проект стоял ~7 месяцев. Крупные мажоры уже свежие (TS 6, ESLint 10, Vite 8, Zod 4) — дрейф в основном минорный/патчевый. Node 24 — действующий LTS (поддержка до 2028), Node 26 получила LTS в конце октября 2026 — окно для переезда правильное. Нативных модулей в зависимостях нет, значит бамп Node — низкорисковый.

Тестов в репо нет, верификация = `lint` + `typecheck` + smoke-сценарий вручную (см. DoD).

## Объём работ

### 1. Инвентаризация

- `npm outdated` — зафиксировать текущее состояние (вывод приложить к PR)
- Проверить `npm audit` на известные уязвимости

### 2. Обновление пакетов

- Минорные/патчевые — пачкой: `npm update`
- Мажоры — по одному, после каждого: `npm run lint` + `npm run typecheck`
- Каждый мажор — отдельным коммитом
- Внимание к точкам роста: `@google/genai`, `@langchain/*`, `@qdrant/js-client-rest` (см. задачи 02/05 — их API трогаем там), `zod` v4 (breaking-изменения схем)

### 3. Переезд на Node 26

- `Dockerfile`: `node:24-alpine` → `node:26-alpine` (обе стадии: base и runner)
- `vite.config.ts`: build target `node24` → `node26`
- `@types/node`: `^26`
- `package.json`: добавить `"engines": { "node": ">=26" }`
- Добавить `.nvmrc` (`26`) для локальной разработки
- Обновить упоминания Node 24 в `README.md` / `AGENTS.md` / корневом `AGENTS.md`

### 4. Пиннинг инфраструктуры

- `docker-compose.yml`: `qdrant/qdrant:latest` → зафиксировать актуальную минорную версию (плюс к задаче 05: версия клиента должна соответствовать API сервера)
- `redis:7-alpine` — ок, не трогать

### 5. Smoke-проверка (вместо тестов)

- `npm run docker:up:local` → `npm run dev`
- Прогнать repo-sync небольшого репозитория
- Прогнать analyze-pr на тестовом PR → комментарий в GitHub пришёл
- Проверить, нужен ли ещё `NODE_OPTIONS=--expose-gc` на Node 26 (см. задачу 06)
