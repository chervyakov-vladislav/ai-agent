# Правила папки `tasks/`

Backlog задач. Имя файла: `NN-slug.md`, нумерация сквозная, номер не переиспользуется. Новая задача получает следующий свободный номер.

## Шкала приоритетов

Приоритет — про порядок выбора задачи, а не про граф зависимостей. Зависимости фиксируются строкой «Зависимости» в таблице, приоритет отвечает на вопрос «что брать в работу, когда есть выбор».

| Приоритет | Смысл                                 | Когда делать                                 | Примеры из бэклога                           |
| --------- | ------------------------------------- | -------------------------------------------- | -------------------------------------------- |
| **0**     | Фундамент — блокирует всё остальное   | Первым, до любых других задач                | 04 (deps update + Node 26)                   |
| **1**     | Высокий — независимые куски ценности  | Сейчас; обычно независимы, можно параллельно | 01 (корпус правил), 08, 09 (multi-VCS)       |
| **2**     | Средний — фичи, часто с зависимостями | После закрытия зависимостей                  | 02 (rules-sync), 05, 10                      |
| **3**     | Низкий — опциональное и рефакторинг   | Когда нет задач 0–2                          | 11 (Bitbucket), 12 (рефакторинг application) |

Конвенции:

- Число можно уточнять текстом после тире: `2 — после Task 04`, `3 — опционально, в корпоративном контуре основная VCS — GitLab`. Уточнение важнее числа.
- Диапазон допустим (`2–3`) — если гибко и не зависит от соседних задач.
- Не выдумывать новые уровни: шкала 0–3 фиксирована.

## Структура задачи

1. Таблица: `Приоритет` / `Зависимости` / `Открывает` (что становится возможным после).
2. `## Контекст` — зачем задача + диагноз текущего кода со ссылками на файлы.
3. `## Объём работ` — фазы или шаги; каждая фаза должна завершаться зелёным `lint` + `typecheck` (тестов в репо нет).
4. `## Технические заметки` — границы задачи: что **не входит** и отложено (например, «BullMQ — вне этой задачи»).
5. `## Критерии приёмки (DoD)` — чекбоксы, каждый проверяем командой (`lint`, `typecheck`, grep-паттерн) или наблюдаемым поведением, не «стало лучше».

Для агента: при добавлении задачи — не пересматривать приоритеты чужих задач сам; если шкала кажется неверной, предложить изменение пользователю.
