# Контекст проекта Gemini CLI: AI-Agent

Этот документ содержит основные сведения и инструкции для проекта AI-Agent — интеллектуального инструмента для автоматического анализа Pull Request'ов с использованием LLM и RAG.

## Обзор проекта

- **Назначение:** Агент для автоматического код-ревью, который анализирует диффы PR, предоставляет обратную связь напрямую в GitHub и использует RAG для понимания контекста кодовой базы.
- **Архитектура:** Модульная/Чистая архитектура с четким разделением ответственности:
  - `application/`: Бизнес-логика (Use Cases), интерфейсы (Ports) и доменные контракты.
  - `interface/`: Первичные адаптеры (контроллеры HTTP/Express, валидаторы).
  - `modules/`: Вторичные адаптеры (GitHub, Gemini, Qdrant, Ollama, Embeddings).
  - `shared/`: Сквозная функциональность (ошибки, логгер, базовые клиенты).
- **Ключевые технологии:**
  - **Runtime:** Node.js 24 (ES Modules).
  - **Язык:** TypeScript 6.
  - **AI:** Google Gemini (@google/genai), LangChain для RAG-пайплайнов.
  - **Инфраструктура:** Qdrant (Vector DB), Ollama (локальные эмбеддинги), Redis (BullMQ для фоновых задач).
  - **Web Framework:** Express 5.
  - **Валидация:** Zod.
  - **Логирование:** Pino.

## Сборка и запуск

### Предварительные требования

- Node.js 24+
- Docker и Docker Compose (для инфраструктуры)
- Действующие `GITHUB_TOKEN` и `GEMINI_API_KEY`

### Локальная настройка

1.  **Инфраструктура:** Запустите необходимые сервисы (Qdrant, Redis, Ollama):
    ```bash
    npm run docker:up:local
    ```
2.  **Окружение:** Создайте файл `.env.development` на основе `.env.example`.
3.  **Разработка:** Запустите приложение в режиме отладки:
    ```bash
    npm run dev
    ```

### Другие команды

- `npm run build`: Сборка проекта с помощью Vite.
- `npm run start`: Запуск собранного приложения.
- `npm run typecheck`: Проверка типов TypeScript.
- `npm run lint`: Проверка стиля кода через ESLint.
- `npm run format`: Форматирование кода через Prettier.

## Конвенции разработки

- **Чистая архитектура:** Держите бизнес-логику в `src/application/use-cases`. Не допускайте утечки деталей инфраструктуры (типы Express, клиенты БД) в слой приложения. Используйте `Ports` для определения контрактов адаптеров.
- **Строгая типизация:** Избегайте использования `any`. Используйте интерфейсы и типы, определенные в `*.types.ts` или `*.contracts.ts`.
- **Валидация:** Всегда валидируйте входящие данные на уровне контроллеров с помощью Zod-схем в `src/interface/http/dto-validators`.
- **Обработка ошибок:** Используйте кастомные классы ошибок из `src/shared/errors`. Все ошибки приложения должны наследоваться от `AppError`. Никогда не выбрасывайте обычные объекты `Error`.
- **Логирование:** Используйте логгер из `src/shared/infrastructure/logger` (Pino). Логируйте полезный контекст, но избегайте логирования чувствительных данных (токены, ключи).
- **Асинхронная работа:** Длительные задачи (индексация, глубокий анализ) должны выноситься в воркеры BullMQ.

## Правила импорта

- **Внешние папки проекта:** Всегда используйте алиасы путей, настроенные в `tsconfig.json`. Доступные алиасы:
  - `@/*` -> `./src/*`
  - `@config/*` -> `./src/config/*`
  - `@shared/*` -> `./src/shared/*`
  - `@modules/*` -> `./src/modules/*`
  - `@application/*` -> `./src/application/*`
  - `@contracts/*` -> `./src/application/contracts/*`
  - `*` -> `./src/*` (используйте осторожно, предпочитайте именованные алиасы)
- **Локальные файлы:** Внутри одной папки (модуля) используйте относительные пути. Пример: `import { someUtil } from './some.utils';`.
- **Внешние библиотеки:** Импортируйте через название пакета из `package.json`. Пример: `import { v4 } from 'uuid';`.
- **Системные модули Node.js:** Всегда используйте префикс `node:`. Пример: `import { createHash } from 'node:crypto';`.

## Безопасность и переменные окружения

- **Защита данных:** Системные переменные и секреты из `.env` файлов **никогда** не должны попадать в контекст Gemini.
- **Инструкция для агента:** Если для работы требуются переменные окружения, агент **не должен** считывать их значения самостоятельно. Вместо этого агент обязан:
  1. Указать названия необходимых переменных.
  2. Указать файл, в который их нужно добавить (например, `.env.development`).
  3. Попросить пользователя добавить эти значения вручную.

## Основные директории

- `src/main.ts`: Точка входа для запуска приложения.
- `src/config/env-config.ts`: Централизованная валидируемая конфигурация окружения.
- `src/application/use-cases/`: Реализация конкретных функций (например, `analyze-pr`, `repo-sync`).
- `src/modules/llm-gemini/`: Интеграция с Google Gemini и управление промптами.
- `src/shared/infrastructure/clients/`: Инициализация общих клиентов (Axios, Redis, Qdrant).
